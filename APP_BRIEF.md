# Описание приложения

## Результат для пользователя

Владелец небольшого фитнес-зала видит клиентов, оплаты и ближайшие сроки продления на любом своём телефоне и не рискует потерять базу при поломке устройства.

## Целевая среда

- Платформы: PWA в актуальных Safari/Chrome на iPhone, Android и компьютере.
- Предполагаемый пользователь: один владелец зала; в будущем возможен доступ доверенного сотрудника.
- Требования к автономной или сетевой работе: просмотр последних данных и безопасное внесение изменений при кратком отсутствии сети с последующей синхронизацией.
- Важные ограничения конфиденциальности: имена, телефоны и платежи являются персональными данными; доступ только после авторизации, данные и секреты не попадают в Git и журналы.

## Сценарий минимальной версии

При первом входе владелец добавляет клиента и оплату, после чего видит клиента в списке со сроком окончания и статусом срочности; после перезапуска или входа с другого телефона данные сохраняются.

## Сценарии приёмки

- [x] Добавление клиента с именем, телефоном, суммой, датой и длительностью абонемента.
- [x] Пустое состояние объясняет, как добавить первого клиента.
- [x] Ошибка хранилища не раскрывает данные и даёт понятное действие; авторизация появится с облачной синхронизацией.
- [x] В настройках видны текущая версия приложения и краткая история изменений.
- [x] У клиента можно сохранить заметку; она видна в карточке и кратко показана в списке.
- [x] Системная кнопка «Назад» возвращает с вложенного экрана или формы, а не закрывает приложение.
- [x] Действующий абонемент можно заморозить; статус и новая дата окончания рассчитаны прозрачно, действие сохраняется в истории.
- [ ] Главный экран помогает быстро найти клиента и сначала показывает тех, кому требуется внимание.
- [ ] При потере сети ранее загруженные данные доступны, изменения не дублируются после восстановления связи.

## Ограничения качества

- Производительность: интерактивный экран после загрузки оболочки без заметных задержек; список из 1000 клиентов прокручивается плавно на среднем телефоне.
- Доступность: управление с клавиатуры, видимый фокус, семантические подписи и контраст не ниже WCAG AA.
- Расход батареи или фоновая работа: нет постоянного опроса; синхронизация по событиям и при открытии.
- Поддерживаемые версии ОС: актуальная и две предыдущие основные версии iOS/Android, если браузер поддерживает необходимые API.

## Явно не входит в минимальную версию

- Публикация в App Store и Google Play.
- Учёт посещений, расписание тренировок, склад, касса и онлайн-эквайринг.
- Push-уведомления до проверки реальной потребности и доставки на устройствах.
- Несколько залов и сложные роли сотрудников.

## Команды проверки

- Сборка: `npm run build`
- Тесты: `npm test`
- Статический анализ и проверка типов: `npm run lint`, `npm run typecheck`
- Полная локальная проверка: `npm run check`
- Запуск: `npm run dev`

## Открытые решения и допущения

- Рабочее имя продукта и репозитория: `Abon` / `abon`.
- MVP публикуется бесплатно через GitHub Pages; каждый push в `main` проходит проверки и автоматически обновляет сайт.
- Для синхронизации MVP используется бесплатный Firebase Spark без платёжной карты; доступ к данным остаётся за интерфейсом репозитория, чтобы backend можно было заменить.
- До появления независимого автоматического хранилища приложение напоминает о ручном JSON-бэкапе; платные функции Firebase для MVP не требуются.
- Для MVP сохраняется совместимость импорта со старым JSON-форматом `gym-tracker`/`setka`, но новая схема получит явную версию.
- Суммы вводятся и хранятся в целых рублях без копеек.
- Даты хранятся как `YYYY-MM-DD`, а в интерфейсе показываются с полным русским названием месяца, например `29 сентября 2026`; статус использует локальный календарный день устройства.
- Телефон можно вводить с `+7`, с `8` или с кода оператора; после сохранения он приводится к виду `+7 XXX XXX-XX-XX`.
- Период заморозки считается от первого дня паузы до дня возобновления, не включая день возобновления; при досрочной разморозке срок продлевается только на фактически использованные дни.

## Функциональные ориентиры

- Старые проекты `D:\Pr\setka` и `D:\Pr\gym-tracker` служат источником состава функций и проверенных бизнес-сценариев, но их устаревший визуальный стиль не копируется буквально.
- Главный экран при наличии клиентов включает количество клиентов, добавление и меню, баннер требующих внимания, поиск и список по срочности.
- Компактная карточка клиента показывает имя, статус, последнюю оплату, срок, дату окончания и одну строку заметки; замороженный статус различим без опоры только на цвет.
- Полный состав, который нужно последовательно пересмотреть и перенести: заметки, заморозка и разморозка, поиск и фильтр срочных, быстрое продление, редактирование, архив, тарифы, резервные копии, авторизация и синхронизация, статистика.
- Поиск на главном экране и в архиве регистронезависимо находит клиента по любой части имени или фамилии, а не только по первым буквам.
- Архивирование не удаляет клиента: архив хранит его данные и историю, позволяет искать и возвращать клиента в активный список; окончательное удаление остаётся отдельным явно подтверждаемым действием.
- Знакомые компактные действия можно обозначать пиктограммами Material Design через общий компонент `Icon`; неоднозначные и рискованные действия сохраняют текст, а кнопки-иконки всегда имеют доступное название.
- Тариф — редактируемый шаблон с названием, суммой в целых рублях и сроком в месяцах. Его можно быстро выбрать при добавлении клиента и оплате, но изменение или удаление шаблона не переписывает уже сохранённые операции.
- Общая заморозка применяется одной массовой операцией к подходящим клиентам с предварительным показом количества и периода. Пересекающиеся личные и общие периоды считаются как объединение дней без двойного продления; полностью перекрытая общая заморозка не добавляет клиенту срок.

## Поэтапный roadmap

Каждый пункт выполняется в отдельном контекстном окне, завершается `npm run check`, просмотром diff, обновлением `docs/PROJECT_STATE.md`, отдельным коммитом и push в `main`.

1. [x] Локальный список клиентов, добавление клиента и первой оплаты, срок и статус.
2. [x] Карточка клиента, история оплат, продление без дублей и миграция локальных данных.
3. [x] Настройки, история версий и полный русский формат дат.
4. [x] Заметки: хранение, редактирование в карточке и однострочный превью-текст в списке.
5. [x] Индивидуальная заморозка: период, отдельный статус, перенос окончания, досрочная разморозка только по фактическим дням и запись в истории.
6. [ ] Общая заморозка при болезни или отпуске тренера: предварительный расчёт затронутых клиентов, связанные записи одной операции и отсутствие двойного продления при пересечении с личными заморозками.
7. [ ] Изолированный demo-набор из 25–30 полностью вымышленных клиентов: разные сроки, статусы, истории оплат, заметки и заморозки; данные не смешиваются с реальной базой.
8. [ ] Полноценный главный экран: сортировка по срочности, баннер требующих внимания, поиск по любой части имени или фамилии, фильтр и компактные информативные карточки.
9. [ ] Редактирование клиента, безопасное архивирование, поиск по архиву, восстановление и отдельное подтверждаемое удаление.
10. [ ] Управляемые шаблоны тарифов: название, сумма и срок; быстрый выбор при добавлении клиента и оплате без изменения сохранённой истории после редактирования или удаления тарифа.
11. [ ] Версионированный JSON-экспорт и безопасное восстановление с совместимостью `gym-tracker`/`setka` и показом возраста копии.
12. [ ] Авторизация, облачная синхронизация и офлайн-очередь идемпотентных изменений.
13. [ ] Статистика по клиентам, оплатам и тарифам после появления надёжных синхронизируемых данных.
14. [ ] Финальная проверка PWA: производительность большого списка, доступность, офлайн-сценарии и реальные iPhone/Android.
