# Решения проекта

## 2026-08-29 — PWA как первая целевая платформа

- **Контекст:** приложение должно работать на Android, iPhone и компьютере, а функции нативных магазинов в минимальной версии не нужны.
- **Решение:** строить mobile-first PWA на React, TypeScript и Vite; нативную обёртку рассматривать только при появлении подтверждённой потребности.
- **Причина:** одна кодовая база, установка с домашнего экрана, быстрое распространение по ссылке и возможность позже завернуть тот же web-код в Capacitor.
- **Последствия:** push и фоновые сценарии требуют отдельной проверки на iOS; публикация в магазинах отложена.

## 2026-08-29 — Данные не зависят от одного устройства или backend SDK

- **Контекст:** потеря телефона или очистка браузера не должна уничтожать клиентскую базу; доступность зарубежных облаков из России нестабильна.
- **Решение:** отделить предметную модель от адаптера хранения; облако будет источником синхронизации, локальная база — офлайн-копией, JSON-экспорт — независимой резервной копией.
- **Причина:** это позволяет сменить Firebase, Cloudflare или российский backend без переписывания интерфейса и расчётов.
- **Последствия:** конкретный backend выбирается после прототипа и проверки на целевых мобильных сетях; все мутации должны быть идемпотентными.

## 2026-08-29 — Системная тема и единый набор Material Design Icons

- **Контекст:** нужен современный, простой и спокойный интерфейс без эмодзи.
- **Решение:** темы следуют системной настройке через `prefers-color-scheme`; все пиктограммы, когда они появятся, берутся из одного набора Material Design через общий компонент.
- **Причина:** единый визуальный язык, меньше ручных настроек и предсказуемый вид на разных устройствах.
- **Последствия:** запрещено смешивать icon-наборы и использовать эмодзи как элементы интерфейса.

## 2026-08-29 — Бесплатный контур MVP

- **Контекст:** приложение нужно быстро передать другу по ссылке, автоматически обновлять после push и не требовать зарубежной оплаты.
- **Решение:** публиковать публичный репозиторий через GitHub Pages; использовать Firebase Spark для синхронизации без подключения биллинга.
- **Причина:** этот контур уже знаком владельцу, бесплатен для масштаба одного зала и позволяет установить PWA на Android и iPhone.
- **Последствия:** исходный код публичен, но секреты и клиентские данные в репозиторий не попадают; автоматические бэкапы Blaze недоступны, поэтому MVP включает версионированный JSON-экспорт и напоминание.

## 2026-08-29 — Календарные периоды заморозки без двойного продления

- **Контекст:** клиент может вернуться раньше запланированного срока, а будущая общая пауза зала может пересечься с личной заморозкой.
- **Решение:** заморозка хранит первый день паузы и день возобновления; день возобновления не входит в паузу. Досрочная разморозка оставляет только фактически использованные дни, а пересекающиеся личные и общие периоды в будущем считаются как объединение календарных дней.
- **Причина:** срок клиента увеличивается ровно на число дней, когда он не мог пользоваться абонементом, без двойной компенсации.
- **Последствия:** записи общей операции связываются идентификатором группы; при частичном пересечении массовый расчёт добавляет только непокрытые дни, а при полном пересечении не меняет срок клиента.

## 2026-08-30 — Собственный версионированный формат резервной копии

- **Контекст:** прототипы `gym-tracker` и `setka` не использовались на практике и их резервных копий не существует.
- **Решение:** экспортировать и восстанавливать только JSON-копии Abon с явными полями `app: "abon"` и `version: 1`; чужие приложения и неизвестные версии отклонять до записи.
- **Причина:** узкий формат можно полностью проверить и безопасно развивать без неподтверждённых преобразований несуществующих данных.
- **Последствия:** будущие изменения формата требуют новой версии и теста миграции; совместимость со старыми прототипами намеренно отсутствует.
