# Состояние проекта

## Текущий результат

Подтверждена реальная офлайн-синхронизация двух устройств; локальная база открывается до завершения облачной загрузки.

## Подтверждённое состояние

- Пустой список объясняет, как добавить первого клиента.
- Форма сохраняет имя, телефон, целую сумму в рублях, дату оплаты и длительность абонемента; телефон принимает начало `+7`, `8` или код оператора и сохраняется как `+7 XXX XXX-XX-XX`.
- Срок рассчитывается календарными месяцами, включая короткие месяцы; статус становится срочным за 7 дней и учитывает локальную дату устройства.
- В подробных экранах дата показывается полным русским форматом, например `29 сентября 2026`, а в компактном списке — как `29.09.2026`; внутри она хранится как `YYYY-MM-DD`.
- Клиенты сохраняются в `localStorage` через интерфейс `ClientRepository` и остаются после перезапуска.
- Повреждённое или недоступное хранилище не раскрывает частичные данные и показывает действие «Повторить».
- Интерфейс адаптивен на ширине от 360 до 1024 px и автоматически следует системной теме.
- Техническое уведомление о готовности офлайн скрыто; приложение сообщает только о доступном обновлении, где требуется выбор пользователя.
- Жест обновления страницы протягиванием вниз отключён через контроль вертикального overscroll; обычная прокрутка сохранена.
- Клиент открывается из списка в отдельную карточку с телефоном, текущим сроком и полной историей оплат.
- Новая оплата продлевает действующий абонемент от текущего окончания, а просроченный — от даты оплаты.
- Каждая операция оплаты имеет стабильный идентификатор, поэтому повтор одной операции не создаёт дубль.
- Старые данные `abon.clients.v1` автоматически переносятся в схему `abon.clients.v2`; исходная запись v1 при этом не удаляется.
- Из списка клиентов открываются настройки с текущей версией и краткой историей выпусков.
- Версии следуют схеме `yymmdd`, затем `.2`, `.3` для следующих выпусков того же дня.
- У клиента можно добавить, изменить или очистить заметку; непустая заметка полностью видна в карточке и одной строкой показана в списке.
- Схема локальных данных обновлена до `abon.clients.v3`; данные v2 и v1 переносятся с пустой заметкой без удаления исходной записи.
- Открытие настроек, карточки клиента и форм добавляет экран в историю браузера; системная кнопка «Назад» возвращает на предыдущий экран.
- Корневой список остаётся естественной точкой выхода из PWA; после успешного сохранения закрытая форма не появляется снова при возврате.
- Действующий абонемент можно заморозить на календарный период; день возобновления не входит в паузу, а дата окончания сразу переносится на число дней заморозки.
- Во время паузы клиент имеет отдельный текстовый статус «Заморожен», период и добавленные дни видны в карточке и в общей истории операций.
- При досрочной разморозке срок сохраняет только фактически использованные дни; повтор операции не меняет данные второй раз.
- Схема локальных данных обновлена до `abon.clients.v4`; данные v3, v2 и v1 переносятся с пустой историей заморозок без удаления исходной записи.
- Запись заморозки поддерживает идентификатор общей операции для будущей массовой паузы зала.
- Перед общей заморозкой видны период, число затронутых клиентов и суммарное количество добавляемых клиент-дней.
- Общая операция атомарно создаёт связанные записи для всех подходящих клиентов; повтор с тем же идентификатором не создаёт дублей.
- Пересекающиеся личные и общие периоды считаются как объединение календарных дней: частичное пересечение добавляет только непокрытые дни, полное — не меняет срок.
- Полностью перекрытая общая запись сохраняется с нулём добавленных дней, чтобы подхватить освободившееся покрытие при ранней личной разморозке.
- Активная общая заморозка завершается для всех клиентов одной операцией и согласованно пересчитывает сроки.
- В настройках можно явно включить demo-режим с 28 полностью вымышленными клиентами, охватывающими просроченные, срочные, активные и замороженные абонементы, разные истории оплат, заметки и завершённые заморозки.
- Demo-операции выполняются в отдельном репозитории в памяти и не читают повторно и не изменяют реальную локальную базу; действие «Выйти и очистить» удаляет временные изменения и возвращает реальные данные.
- Demo-режим отмечен компактным бейджем в заголовке, а выход и очистка находятся в настройках; временные данные различимы без отдельного баннера, занимающего экран.
- На главном экране клиенты автоматически отсортированы по сроку: сначала просроченные и заканчивающиеся, затем активные, внизу замороженные.
- Баннер внимания показывает просроченных и заканчивающихся в ближайшие 7 дней; нажатие сразу включает соответствующий фильтр.
- Поиск по любой части имени и фильтр статуса работают совместно и не изменяют данные.
- Компактная карточка показывает имя, статус, дату и сумму последней оплаты, дату окончания, длительность и одну строку заметки; номер телефона доступен только в подробной карточке.
- Общая заморозка перенесена с главного экрана в настройки как редкая операция.
- Основные действия добавления клиента и новой оплаты доступны через плавающую кнопку с Material-пиктограммой; остальные пиктограммы проходят через общий компонент `Icon`.
- Функциональные находки старого проекта не переносят его оформление: главный экран использует исходные зелёную палитру, поверхности, типографику и скругления Abon без цветных боковых полос и чужой синей шапки.
- Имя и телефон клиента можно изменить без изменения оплат, заметки и истории заморозок.
- Архивирование требует подтверждения и не удаляет данные; архивный клиент скрыт из рабочего списка, доступен через отдельный поиск и может быть восстановлен.
- Безвозвратное удаление доступно только для архивной записи и требует отдельного явного подтверждения.
- Схема локальных данных обновлена до `abon.clients.v5`; данные v4, v3, v2 и v1 переносятся с активным статусом без удаления исходной записи.
- Карточка клиента, архив и настройки используют компактную одноуровневую шапку и плотные карточки в ритме главного экрана.
- На главной под шапкой сохранён зазор 12 px, счётчик требующих внимания показан один раз, декоративный знак `A` перед заголовком убран.
- Тарифы с названием, целой суммой в рублях и сроком в месяцах можно создавать, изменять и удалять в настройках.
- Выбор тарифа в формах нового клиента и новой оплаты подставляет сумму и срок; после подстановки поля остаются редактируемыми вручную.
- Тарифы хранятся отдельно в `abon.tariffs.v1`; оплаты сохраняют собственный снимок суммы и срока, поэтому изменение или удаление шаблона не переписывает историю.
- Demo-тарифы работают в отдельном репозитории в памяти и очищаются вместе с остальными demo-изменениями.
- В настройках можно скачать JSON-копию всех клиентов и тарифов в собственном формате Abon версии 1.
- Импорт принимает только копии Abon известной версии, проверяет структуру, все записи и уникальность идентификаторов до записи.
- Замена базы начинается только после отдельного подтверждения; при ошибке приложение пытается вернуть предыдущие данные.
- В настройках виден возраст последней созданной независимой копии; резервные операции отключены в demo-режиме.
- Форматы неиспользованных прототипов `gym-tracker` и `setka` намеренно не поддерживаются.
- Добавлен вход владельца по одноразовой email-ссылке Firebase Authentication; сессия сохраняется локально до явного выхода.
- Первый подтверждённый пользователь получает собственный `gymId`; локальные клиенты и тарифы один раз переносятся в Cloud Firestore.
- Локальная база остаётся офлайн-копией: изменения попадают в постоянную очередь, операции имеют уникальные идентификаторы и повторно не применяются в облаке.
- После прежнего успешного входа холодный запуск без сети открывает локальные данные без обращения к облаку; при восстановлении сети очередь отправляется автоматически.
- После определения владельца интерфейс показывает локальную базу сразу, а первоначальная облачная сверка продолжается в фоне.
- Firestore создан в регионе `asia-northeast1` (Tokyo) на тарифе Spark; правила разрешают доступ только владельцу профиля и участнику соответствующего зала.
- GitHub Pages получает публичную web-конфигурацию Firebase из repository variables; `.env.local` игнорируется Git и остаётся на компьютере.
- Текущая версия приложения — `260830.7`.

## Ограничения и блокеры

- Запрет доступа постороннему аккаунту обеспечен опубликованными Firestore Rules, но ещё не проверен отдельным реальным аккаунтом или эмулятором правил.
- Установка PWA и офлайн-изменение на физическом устройстве подтверждены владельцем; ускоренный запуск локальной базы версии `260830.7` ещё нужно проверить на опубликованной сборке.

Завершить приёмку этапа 12 на опубликованной версии `260830.7`: проверить быстрый холодный запуск без сети и отказ доступа отдельному авторизованному аккаунту.
